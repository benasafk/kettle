# Kettle product jobs

Oct 5, 2026 · @Gustas

## How to read this

Every job goes to whoever can do it best at the lowest cost and risk. ChatGPT does the talking and thinking it already does, Kettle's server does what ChatGPT can't, and people do what needs judgement or a signature. Each section below lists the jobs for one area of the product. Frame names in brackets, such as (2B), point to the Paper design.

**The rule behind every "who":**

- **ChatGPT, guided by Kettle's skills, handles the conversation:** understanding what people bring, asking questions and making small rewrites. It's already in the chat, and the user's ChatGPT plan pays for it.
- **Kettle's server handles what ChatGPT can't:** live video data, memory across chats, work that takes minutes, rules that must always hold, identity and money.
- **The panel appears only where people compare, choose or work through a long structured result.** Everything else stays in chat, so Kettle works without the panel too.
- **Specialist services each do their one thing:** Auth0 for sign-in, Stripe for payments, Supabase for storage, Lightreel for references. Kettle buys these rather than building them.
- **People handle what needs judgement or a signature:** rights deals, legal policies, support and pricing.
- **Money never moves inside ChatGPT.** OpenAI's rules forbid selling subscriptions or credits in a plugin, so all selling happens on Kettle's website.

**Who's who:**

## The three actions that matter most

Three user actions decide whether Kettle succeeds: choosing an idea, getting the script out to film it, and refining in chat. Each diagram below shows who does what for that action in the full product. Calls from the panel pass through ChatGPT's bridge to Kettle's server, but they're drawn as direct arrows for readability.

### 1. Choose an idea to film

&#91;embedded content: Choose an idea to film · UML sequence, 6 participants\]

Accepting the top pick skips straight to Open in Studio. If writing fails, version 4 keeps the previous script with an error note. Logging the pick gives Kettle its pick rate, the first sign that references and scripts land.

### 2. Get the script out and film it

&#91;embedded content: Get the script out and film it · UML sequence, 4 participants\]

Plain text in chat always works. Copy in the panel depends on whether the browser allows it. Recording the filmed date gives Kettle its filmed rate, the truest measure of value.

### 3. Refine in chat

ChatGPT knows which video is #2 because the panel shares what's on screen. Each refinement is a paid Lightreel search, counted separately from the $0.90 ceiling. Check 5 passes when new alternatives appear within 5 seconds of version 6 being ready.

## Studio

In Studio, ChatGPT does the rewriting and Kettle's server keeps versions, timing and rules. Edits made in chat cost Kettle nothing per edit.

| Job | Who | Why |
| --- | --- | --- |
| Show the complete filming guide (3A) | Panel, full screen | A long, structured script with parts and shots needs room. |
| Edit a line from chat, such as "make the hook punchier" (3C) | ChatGPT rewrites; Kettle server checks the result and saves a new version | ChatGPT is already in the chat and paid for. The server still rejects a broken structure or an invented number. |
| Offer Keep mine or Use new (3D) | Panel shows both; Kettle server keeps both versions | The choice is visual. The record must survive the chat. |
| Undo (3E, 2B·F-1) | Kettle server, by restoring the previous version | Undo only works if every version is kept. |
| Estimate how long each line takes to say | Kettle server, from words per second for the language | It's arithmetic, so it should give the same answer every time. |
| Shorten a script to a target length, such as 22 s to 15 s (3B) | ChatGPT rewrites; Kettle server measures and confirms the new length | Rewriting is language work. Measuring is arithmetic. |
| Make a no-talking or no-face version (3F, 2B·F-3) | ChatGPT rewrites, following the skill's rules; Kettle server saves it as a variant | The skill holds the on-screen-text conventions. The server keeps the variant linked to the original. |
| Fill the gaps marked \[ \] in founder scripts (2B·F-1) | ChatGPT asks; Kettle server records the fact and its source | A gap is a fact only the founder knows, and the source must stay attached. |

| Swap one part for one from a library | Panel starts it; Kettle server saves a new version | Links Studio to Explore without losing the old version. |

## Accounts, plans and billing

All selling happens on Kettle's website, and the plugin only serves people who already have an account. OpenAI's plugin guidelines forbid selling digital subscriptions or credits in a plugin, and they count freemium as selling.

| Job | Who | Why |
| --- | --- | --- |
| Create a Kettle account | Auth0, from Kettle's website or the first ChatGPT link | Auth0 handles passwords, social sign-in and two-step login, so Kettle never stores passwords. |
| Link ChatGPT to the Kettle account | ChatGPT app and Auth0, using the standard secure sign-in flow (OAuth with PKCE) | ChatGPT requires this flow for plugins with accounts. |
| Check the access token on every call | Kettle server | OpenAI requires full token checks on every request. |
| Show plans and prices, and handle upgrades | Kettle website only | Showing plans, promoting upgrades or linking to checkout inside a plugin is not allowed. |
| Take payment and run the $49 a month subscription | Stripe Checkout and Stripe's billing portal, on the website | Stripe handles cards, retries, receipts and cancellation. |
| Keep each account's plan in sync | Kettle server, from Stripe's webhook messages | The server must know who has paid, at the moment they call a tool. |
| Enforce monthly usage limits, such as runs and refinements | Kettle server | Protects the $0.90 per 2B cost ceiling and the planned \~10 runs per user each month. |
| Tell someone they've reached a limit | ChatGPT, stating the fact and the reset date, with no upgrade prompt | A neutral status is fine. Promoting an upgrade inside the plugin isn't. |
| Offer any free trial | Kettle website, before the person links ChatGPT | A free tier inside the plugin would count as selling under OpenAI's rules. |
| Charge EU VAT and issue invoices | Stripe Tax and Stripe invoices | Digital services sold to EU customers need VAT handled per country. |
| Handle refunds and billing questions | Kettle team, using Stripe's dashboard | Refunds need a person's judgement. |
| Give OpenAI's reviewers a working demo account | Kettle team, with Auth0 | Review requires logging in with no extra setup. |
| Disconnect ChatGPT from an account | ChatGPT app, plus a "connected apps" setting on Kettle's website | People should be able to cut the link from either side. |

## Trust, rights and safety

The biggest risk to Kettle is legal, not technical: written permission to use reference content commercially is the gate before launch. The rest splits between rules the server enforces and policies the team owns.

| Job | Who | Why |
| --- | --- | --- |
| Get written permission to use reference links, numbers and posters commercially | Kettle team, with a lawyer, in the provider contract | Lightreel's terms say access to third-party content doesn't grant permission to reuse it. |
| Credit every reference: creator, platform, link (decision D6) | Panel shows it; Kettle server stores it | Creators get credit, users can check the source, and it supports the rights position. |
| Show only numbers that came from a source, with the date they were observed | Kettle server stores them; the skill forbids ChatGPT to invent any | 2B's notes require source-backed views and never invented results. |
| Keep invented facts about the user's business out of scripts | Kettle server check, plus the skill's rule | Instructions alone can be ignored. A server check can't. |
| Adapt a format without copying a creator's script word for word | Worker writing rules, plus a similarity check on the server | Reusing a format is fine. Copying someone's words is not. |
| Refuse harmful or deceptive scripts, such as fake reviews or false health claims | ChatGPT's own safety rules, the skill's rules, and OpenAI's moderation check on Kettle's background writing | Three layers, because background writing never passes through ChatGPT's own checks. |
| Remind creators to label paid partnerships | ChatGPT, following the skill, when a script promotes a brand the creator doesn't own | Advertising rules in the EU, UK and US require disclosure. |
| Write the privacy policy and terms of service | Kettle team, with a lawyer; published on the website | Required for OpenAI submission and by law. |
| Meet GDPR: lawful basis, data processing agreements with Auth0, Supabase, Lightreel, OpenAI and Stripe, EU data storage | Kettle team | Kettle will serve EU users. |
| Store only what's needed | Kettle server | Less stored means less to protect and less to delete. |
| Export or delete someone's data on request | Kettle server, started from Kettle's website or by support | A GDPR right, and expected by OpenAI's privacy guidance. |
| Delete old data on a schedule | Kettle server, with automatic clean-up jobs | Data kept forever is a growing liability. |
| Lock down data access so each person sees only their own records | Supabase row-level security and Kettle server checks | A bug in one tool shouldn't expose another user's projects. |
| Set a minimum age | Kettle team, in the terms of service | TikTok and ChatGPT require users to be at least 13, and some EU countries need parental consent below 16. |
| List a support contact | Kettle team | Required for OpenAI submission. |

## Platform and operations

The production setup follows your architecture plan: Cloud Run for the server, Cloud Tasks for background jobs, Supabase for data. The prototype runs the same code on your computer with a simpler job queue.

| Job | Who | Why |
